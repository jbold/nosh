# Implementation Plan: Nosh Specification v1.0

**Branch**: `001-nosh-spec` | **Date**: 2026-02-08 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-nosh-spec/spec.md`

## Summary

Define the Nosh open specification for per-page machine-readable companion
files (nosh.json) for AI agents. Deliverables: the specification document
(Markdown), a formal JSON Schema (draft 2020-12), a Zola template for
auto-generating nosh.json files from blog posts, and a Rust-based validator
CLI. The spec covers schema definition, content type taxonomy (10 types),
4 discovery mechanisms, semver versioning, and explicit relationship
boundaries with llms.txt, JSON-LD, and other web standards.

## Technical Context

**Language/Version**: Rust 1.75+ (validator CLI), Zola 0.19+ (Tera templates)
**Primary Dependencies**: `jsonschema` crate (jsonschema-rs) for JSON Schema
draft 2020-12 validation, `clap` for CLI argument parsing, `serde`/`serde_json`
for JSON handling
**Storage**: Filesystem (static JSON files, no database)
**Testing**: `cargo test` (Rust unit/integration tests), manual Zola build
verification, JSON Schema validation test suite (known-good + known-bad files)
**Target Platform**: Cross-platform CLI binary (Linux, macOS, Windows), static
site generator output
**Project Type**: Multi-directory — spec docs + validator CLI + Zola template
**Performance Goals**: Validator processes 1,000 nosh.json files in <5 seconds;
individual file validation in <10ms
**Constraints**: Single-binary distribution (no runtime dependencies), nosh.json
files <1 MB recommended, max nesting depth 3 (required) / 4 (optional)
**Scale/Scope**: Spec v1.0 with 10 content types, 4 discovery mechanisms, 32
functional requirements

**Structure Decision**: Three top-level directories mapping to the three
deliverables: `spec/` (the specification document and schemas), `validator/`
(Rust CLI tool), and `zola-template/` (reference implementation for static
site generation). Each is independently usable — a site owner can adopt the
spec without the validator, or use the validator without Zola. The `spec/`
directory is the core; the other two are reference implementations.
